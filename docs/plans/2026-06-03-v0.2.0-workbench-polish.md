# AI Content Factory v0.2.0 - 工作台打磨与扩展

> **目标：** 把 v0.1.0 的"功能可用"提升到"产品可信赖"，聚焦 UX 一致性、设置面板完整化、模板体系扩展、类型与安全清理。
>
> **不做：** 云同步、团队协作、新平台（视频号/知乎等）。这些放到 v0.3.0+ 评估。
>
> **节奏：** 4 个里程碑，每个里程碑独立可发布、可回滚。

---

## 版本主题

**"让工作台真正成为工作台"** —— 当前版本能生成内容，但仍像一个 Demo。v0.2.0 让它有"产品手感"：设置可调、状态稳定、错误能恢复、模板能自定义。

---

## 北极星指标

1. **零摩擦上手**：新用户从打开页面到拿到第一份内容，无需读文档。
2. **可信赖的状态**：网络中断、API 报错、刷新页面后，用户的输入和历史不丢失。
3. **可调控的体验**：设置面板真实可用，用户能自定义 Provider、默认导出格式、外观偏好。

### M2.2 自定义 Provider 实际接入 ✅

**已完成：**
- `src/lib/settings.ts` 重构为 `useSyncExternalStore` 兼容的 store：新增 `getSettingsSnapshot`、`getSettingsServerSnapshot`，缓存上次解析结果避免反复 JSON.parse；`subscribeSettings` 同时支持跨标签同步（监听 storage 事件）
- `src/types/providers.ts` 扩展 `UserSettings`，新增 `GenerationPreferences`、`AppearancePreferences`
- `src/components/CustomProviderForm.tsx` 复活，从 `SettingsPanel` 的"添加"按钮触发；顺便修复历史遗留的 `border-border` 类（项目里未定义，等于一直没生效），统一改为 `border-border-subtle`
- `src/components/ProviderSwitch.tsx` 把自定义 Provider 与后端 `/api/providers` 的内置列表合并展示，添加/删除后通过 subscribe 实时刷新；徽章对自定义 Provider 显示「自定义」而不是 `__CUSTOM__`
- `src/lib/providers.ts` 新增 `resolveCustomProvider()`，把请求体里的 customProvider 包装成 `ResolvedProvider`，复用 `buildHeaders` / `buildRequestBody` / `getChatEndpoint`

- `src/app/page.tsx` 跟踪 active Provider id+model；选中自定义 Provider 时从 settings 取 baseUrl/apiKey 拼装 `customProvider` 注入请求体

完整链路打通：设置面板添加 Provider → ProviderSwitch 立刻列出 → 选中后生成请求经 customProvider 路由到用户自己的 API。

### M2.3 设置入口替换 ✅

## 里程碑 M3：状态稳定与体验细节（P1 — 2~3 天）

> 让用户敢长时间使用：不怕刷新、不怕失败、不怕被打断。

### M3.1 表单草稿持久化 ✅

**已完成：**
- 新建 `src/hooks/useDraft.ts`：泛型 hook，按 `key` 命名空间存进 localStorage；写入 debounce 300ms；暴露 `clearDraft`
- 实现用「上一次 key 存进 useState + render 中条件 setState」的派生 state 模式，避开 React 19 `react-hooks/set-state-in-effect` 与 `refs` 规则
- `GenerateForm` 改用 `useDraft<DraftShape>`，key = `acf:draft:${platform}:${contentType}`；切换平台/内容类型自动加载对应草稿
- `onGenerate` 改返回 `Promise<boolean>`，调用方明确返回 true 时清空草稿；失败时保留，方便用户修正后直接重试

### M3.2 错误边界与可恢复错误 ✅

**已完成：**
- 新建 `src/components/ErrorBoundary.tsx`（class component + `getDerivedStateFromError`），在 `src/app/layout.tsx` 包裹 children；"重新尝试"按钮 reset 子树
- `src/app/page.tsx` 新增 `classifyError`，把错误按 `timeout / server / config / network / unknown` 分类，针对 config 类额外提示"检查 API Key / baseUrl / 切 Provider"
- 错误面板内置「重试」按钮，用 `lastParams` 直接重发上次请求；同时支持「关闭」清错误

### M3.3 流式生成的完成状态 ✅

**已完成：**
- 流式结束记录 `streamStats = { chars, ms }`，在 ResultDisplay 上方展示 ✓ "生成完成 · 共 N 字 · M 秒"
- 用 `performance.now()` 计时，避免依赖 `Date.now()` 在某些静态分析下的限制
- 仅流式生成路径会设 streamStats；非流式不显示（避免误导）

### M3.4 字符计数与平台限制提示 ✅

**已完成：**
- `GenerateForm` topic 字段右上角加字符计数，按平台显示「N / 建议 M」，超过软阈值变琥珀色提示
- 软阈值：小红书 20 字、抖音 50 字、公众号 30 字（仅主题层面，与下游正文限制不冲突）
- `ResultDisplay` 接收 `platform` prop，结果底部加一条 Info 提示行：小红书正文 ≤1000 字 / 抖音 ≤800 字 / 公众号 ≤5000 字，并显示当前正文字数

## 风险与权衡

- **依赖膨胀风险**：新增 `marked` + `dompurify` 会增加 ~30KB gzipped。可考虑只在导出按钮点击时动态 import。
- **设置面板复杂度**：把自定义 Provider 暴露给用户后，错误支持成本会上升。需要在设置面板里做好"连接测试"和清晰的报错。
- **模板膨胀**：模板从 6 个到 18 个，要避免"看起来很多但用起来都差不多"。每个模板的 topic / keywords / tone 必须真正差异化。
